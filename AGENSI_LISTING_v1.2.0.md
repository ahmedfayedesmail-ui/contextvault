## Full description — proposed copy

# ContextVault

ContextVault gives compatible local AI coding agents a way to search a developer's indexed codebase and retrieve relevant code snippets by meaning.

Instead of relying only on files already opened in a conversation, your agent can query a local semantic index and find implementation details using natural-language questions.

> **You must install ContextVault locally first.** The Agensi skill provides instructions only. It does not install or host the ContextVault application, Ollama, or the local MCP server.

## What it does

- **Semantic code search:** Search indexed project content with natural-language queries through the `search_context` MCP tool.
- **Local project indexing:** Scan a developer-selected project directory through `index_project`.
- **Local embeddings:** Generate embeddings with Ollama and the `nomic-embed-text` model.
- **Local storage:** Store indexed files, chunks, and embeddings in a local SQLite database.
- **Agent context retrieval:** Return relevant file paths and code snippets to the connected AI agent through MCP.

## How it works

1. Install the ContextVault application on the same computer as your supported local AI coding client.
2. Make sure Ollama is running and the `nomic-embed-text` model is installed.
3. Start ContextVault and connect its local MCP server to Claude Desktop or Cursor using the machine-specific configuration generated by the application.
4. Ask your agent to index a project. The agent should request the exact absolute project path and your authorization before indexing.
5. Ask natural-language questions about the indexed codebase. The agent uses `search_context` to retrieve relevant snippets and file paths.

## What you need

- ContextVault installed locally from the GitHub repository.
- Node.js 22.13 or newer.
- Ollama with the `nomic-embed-text` embedding model.
- A local AI client that can launch a stdio MCP server. The setup documented in the current project guide covers **Claude Desktop** and **Cursor**.

For platform-specific instructions, see the [ContextVault installation and MCP setup guide](https://github.com/ahmedfayedesmail-ui/contextvault/blob/main/README_MCP.md).

## Privacy and data handling

Project scanning, embedding generation, and SQLite index storage run locally through ContextVault and Ollama; ContextVault does not send source files to a hosted embedding API for vector generation.

When the agent asks ContextVault for results, the returned code snippets enter the AI agent's context. The agent provider may process those snippets under its own data-handling terms and settings. Therefore, the full workflow should not be described as fully offline unless the AI model itself is also running locally.

Only index project folders you own or are authorized to inspect. Avoid indexing credentials, private keys, or other secrets.

## Use cases

- Build a searchable index of a local codebase.
- Find relevant implementation snippets without knowing exact filenames.
- Explore unfamiliar or legacy projects.
- Trace where a function or implementation pattern appears.
- Retrieve code context for architecture and debugging questions.

## Known limitations

- The Agensi skill is an instruction package; it does not install or host the local application or MCP server.
- The documented local MCP setup currently supports Claude Desktop and Cursor. Cloud-only or web/mobile agents that cannot launch a local stdio process cannot directly access the local ContextVault server.
- The current MCP server exposes two tools: `index_project` and `search_context`.
- MCP search does not currently provide project-scoped filtering within a shared local index. Inspect returned file paths and confirm the target project before relying on results.
- The MCP interface does not expose a separate live-monitoring control. The local desktop application can monitor new and changed files while it remains running after indexing.
- ContextVault retrieves code context; it does not edit source files, run tests, or deploy projects.

## FAQ — proposed answers

**Does the Agensi skill install ContextVault for me?**  
No. The Agensi package contains agent instructions. Install the ContextVault application, Ollama, and the local MCP server separately by following the setup guide.

**Can I use ContextVault with ChatGPT web or mobile?**  
Not for direct access to the local ContextVault MCP server. The local integration requires an AI client that can launch a local stdio MCP process. The currently documented clients are Claude Desktop and Cursor.

**Does my source code get sent to an embedding API?**  
No. ContextVault creates embeddings with your local Ollama service and stores the index in local SQLite. However, snippets returned to your AI agent may be processed by that provider under its own data-handling terms.

**Does the index update automatically?**  
The local ContextVault application can monitor new and changed files after indexing while it remains running. The current MCP tool interface does not expose a separate watcher-management tool.

**Which MCP tools are available?**  
The local ContextVault MCP server currently exposes `index_project` for indexing a developer-selected directory and `search_context` for semantic search of the local index.

**Where do I find installation instructions?**  
Use the [ContextVault installation and MCP setup guide](https://github.com/ahmedfayedesmail-ui/contextvault/blob/main/README_MCP.md).
