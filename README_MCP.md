# ContextVault MCP Server — Setup and User Guide

For the planned fresh-install, MCP Inspector, indexing, search, and embedding-latency checks, follow the [Comprehensive testing guide](TESTING.md).

ContextVault gives a compatible local AI coding client access to a semantic index of a project on the same computer. The application indexes selected project files, generates embeddings with local Ollama, and stores the index in local SQLite. Its MCP server exposes two tools: `index_project` and `search_context`.

## Important: the application, the local MCP server, and the Agensi skill are separate

There are three distinct pieces:

1. **ContextVault application** — the local app, dashboard, indexer, Ollama integration, and SQLite database. Install it from this GitHub repository.
2. **ContextVault local MCP server** — the stdio server that exposes `index_project` and `search_context` to a local AI client. Configure it separately in that client.
3. **ContextVault on Agensi** — an agent-instruction skill (`SKILL.md`) distributed by Agensi. Installing or invoking the Agensi skill does **not** download the ContextVault application or configure the local MCP server. Agensi's marketplace MCP connection is separate from ContextVault's local MCP connection.

For ContextVault code search to work, the local application must be installed and the local MCP tools must be connected to the same AI client that is using the skill. Do not assume the Agensi connection provides the ContextVault tools.

## Supported local MCP clients

The setup documented and maintained in this guide covers:

- **Claude Desktop**
- **Cursor**

Another client may work if it supports a local stdio MCP server and can launch the machine-specific command generated by ContextVault, but that setup is not documented here.

A cloud-only agent or a web/mobile agent that cannot launch a local stdio MCP process cannot directly access the local ContextVault server. ContextVault does not currently provide a hosted remote MCP endpoint or a tunnel service. In particular, installing the Agensi skill in an agent does not bypass this local-connection requirement.

## 1. Install the ContextVault application

Download the repository ZIP from [GitHub](https://github.com/ahmedfayedesmail-ui/contextvault) using **Code → Download ZIP**, then extract it. Run the installer from the extracted repository root — the folder that contains `package.json` and the platform installer.

### Windows 10 22H2 / Windows 11

1. Open the extracted `contextvault` folder.
2. Right-click `install-contextvault.ps1` and choose **Run with PowerShell**.
3. The installer checks for a supported Node.js runtime and installs a Node.js 22 runtime if needed.
4. It locates or installs Ollama, starts the local service, downloads `nomic-embed-text` if missing, and installs the project dependencies.
5. It creates a **ContextVault** desktop shortcut and starts the application.
6. The dashboard opens at [http://localhost:3737](http://localhost:3737).

The first setup needs an internet connection to download dependencies and the embedding model. The model download may be large.

If the desktop shortcut already exists, double-click **ContextVault** to start the app again. The repository also contains `start-contextvault.bat` for a visible terminal launcher.

### macOS 14 Sonoma or newer

1. Open Terminal in the extracted `contextvault` folder.
2. Run:

   ```bash
   bash ./install-mac.command
   ```

3. The installer prepares Homebrew if needed, installs Node.js 22 and Ollama, starts Ollama, downloads `nomic-embed-text`, installs dependencies, and creates a Desktop launcher.
4. The local dashboard opens at [http://localhost:3737](http://localhost:3737).

### Linux (supported 64-bit APT- or DNF-based distributions)

1. Open a terminal in the extracted `contextvault` folder.
2. Run:

   ```bash
   chmod +x install-linux.sh && ./install-linux.sh
   ```

3. The installer uses `sudo` to install Node.js 22 and Ollama, downloads `nomic-embed-text`, installs dependencies, and creates an application launcher.
4. Open [http://localhost:3737](http://localhost:3737) if it does not open automatically.

## 2. Index your first project

1. Open the ContextVault dashboard at [http://localhost:3737](http://localhost:3737).
2. In **Get started with ContextVault**, enter the full absolute path to a local project folder that you own or are authorized to inspect.
3. Select **Index Project**.
4. Wait for indexing to complete. The dashboard reports the files and chunks processed.
5. Ask a natural-language question in the search box and select **Search**.
6. The dashboard starts live monitoring for new and changed files after indexing while the application remains running.

Files excluded by the scanner's ignore rules are not indexed. Do not index repositories or folders without authorization.

## 3. Connect the local MCP server to Claude Desktop or Cursor

Do this on the same computer where ContextVault is installed.

1. Start ContextVault and open [http://localhost:3737](http://localhost:3737).
2. Open **Settings**.
3. Under **AI Integrations**, select **Copy MCP Configuration**.
4. Open the MCP configuration for your chosen client.
5. Merge the generated `contextvault` entry into the existing MCP server configuration. **Do not replace the whole file or remove other MCP servers.**
6. Save the configuration and fully restart the desktop client.
7. Confirm that the client lists both `index_project` and `search_context` as available tools.

ContextVault generates machine-specific settings, including the actual Node.js executable, MCP entry point, SQLite database path, Ollama URL, and required runtime options. Use the generated JSON; do not guess or manually invent these values.

### Claude Desktop configuration file

- Windows: `%APPDATA%\\Claude\\claude_desktop_config.json`
- macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Linux: `~/.config/Claude/claude_desktop_config.json`

### Cursor configuration file

Use one of:

- Project-specific: `.cursor/mcp.json` in the project folder.
- Global: `~/.cursor/mcp.json`.

Paste or merge the generated `contextvault` entry, save, and restart Cursor.

## 4. Verify the connection and use the tools

After restart, confirm that the AI client exposes:

### `index_project`

Indexes a local project directory.

- Required input: `rootPath` — the absolute path to the project directory.
- Only run it when the user explicitly authorizes indexing and provides the intended path.

### `search_context`

Searches the local index using natural language.

- Required input: `query` — the search question.
- Optional input: `limit` — maximum result count (1–100; default 5).

A good first test after indexing is: “Use ContextVault to find where authentication requests are validated. Show the matching file paths and relevant snippets returned by the search.”

## What ContextVault's MCP interface does not expose

The current MCP interface exposes only `index_project` and `search_context`. It does not expose project listing, project-scoped search filters, index-statistics tools, file editing, test execution, deployment, or a separate live-monitoring control. Live file monitoring is an application feature in the local dashboard while ContextVault is running.

If more than one project is indexed into the same local database, `search_context` has no project-path filter. Review returned file paths and confirm which project the results belong to before relying on them.

## Data handling and privacy

- File scanning, embedding generation, semantic search, and SQLite persistence run locally in ContextVault using the local Ollama service.
- ContextVault's indexing process does not send project files to a hosted embedding API.
- When the MCP server returns relevant code snippets to an AI client, those snippets enter the AI provider's context and may be processed under that provider's own terms and data-handling settings. Do not describe the whole workflow as fully offline unless the connected AI model is also local.
- ContextVault writes index data to its local SQLite database; it does not edit the project's source files during indexing.

## Embedding performance and diagnostics

When the local dashboard or local MCP server starts, ContextVault sends a small background warm-up embedding request to Ollama. This loads `nomic-embed-text` before the first user search without delaying the app or MCP connection from starting. The warm-up is non-fatal: if Ollama is unavailable, the app and MCP server still start and log the reason.

Embedding requests keep the model loaded for 30 minutes by default. The request timeout defaults to 120 seconds. You can override these settings with environment variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `OLLAMA_KEEP_ALIVE` | `30m` | How long Ollama should keep the embedding model loaded after a request. |
| `OLLAMA_EMBED_TIMEOUT_MS` | `120000` | Maximum time to wait for one embedding request. Values below 1000 are ignored. |
| `OLLAMA_URL` | `http://localhost:11434` | Local Ollama API base URL. |

ContextVault logs the wall-clock embedding duration for every successful request. When Ollama returns timing metadata, the log also includes model-load and total server time. Timeout and HTTP errors are logged with elapsed time and a clear error message. During project indexing, ContextVault sends chunks to Ollama in batches of up to 16 texts per `/api/embed` request, preserving atomic persistence per file. Search profiling separately logs embedding duration and local vector-search duration for both the HTTP search route and the MCP `search_context` tool. Diagnostics are persisted to `embedding.log` under `%LOCALAPPDATA%\\ContextVault\\logs` on Windows, `~/Library/Logs/ContextVault` on macOS, or `~/.local/state/contextvault/logs` on Linux. Set `CONTEXTVAULT_LOG_DIR` to override the log directory. Use these logs to distinguish model-load delay from ongoing embedding latency; warm-up may reduce cold-start delay but does not guarantee a fixed search time on every computer.

## Troubleshooting

- **The tools are missing after restart:** Confirm the ContextVault app is running; open Settings → AI Integrations → Copy MCP Configuration again; ensure the generated entry was merged into the correct client config; then fully restart the client.
- **Ollama is unavailable:** Confirm the Ollama service is running and `nomic-embed-text` is installed.
- **Search returns no useful matches:** Confirm the intended project was indexed, then retry with a more focused query. Ask before indexing again.
- **The agent claims it can use ContextVault but no tools are listed:** The Agensi skill may be loaded, but the separate local ContextVault MCP server is not connected. Follow section 3 and verify the two tool names before asking the agent to perform code search.
